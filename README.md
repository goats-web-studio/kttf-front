# kttf-front

React PWA. Отдельное приложение, собирается Vite в статику и раздаётся Caddy.

## Запуск

```
pnpm install
pnpm dev          # дев-сервер, /api проксируется на localhost:3000
pnpm build        # typecheck + сборка в dist/
pnpm test         # vitest
pnpm lint         # eslint с type-aware правилами из общего кода
pnpm check:shared # связка с @kttf/shared: тот же SHA, что в kttf-back
```

Бэкенд отдаёт API без CORS. В деве фронт и API живут на одном origin за счёт
прокси, в проде — за счёт общего домена. `VITE_API_URL` нужен только если адрес
API отличается, см. `.env.example`.

## Одно приложение, не два

Публичная часть, кабинеты и консоль судьи живут здесь вместе: одна точка входа,
одна установка PWA, одна сессия. Отдельного приложения под консоль нет и не
будет — ADR-004.

## Маршруты

Файловые маршруты TanStack Router, дерево в `src/routeTree.gen.ts` генерируется
плагином при сборке и лежит в репозитории готовым. Разделены по оболочкам —
они несводимы, и это не оформление:

| Ветка     | Оболочка                 | Что внутри                               |
| --------- | ------------------------ | ---------------------------------------- |
| `_public` | шапка, футер             | рейтинги, календарь, профили, вход       |
| `_app`    | кабинет, вход обязателен | охрана в `beforeLoad`, одна на всю ветку |
| `console` | во весь экран, без шапки | проведение турнира в зале                |
| `screen`  | голая, без авторизации   | второй экран по публичному токену        |

`src/routes/` — только связывание: экраны и логика живут в `src/features/*`.

## Что из этого следует для консоли

`src/features/console/` — модуль проведения турнира в зале. Три требования,
которые нельзя нарушить:

1. **Ввод счёта никогда не ждёт сеть.** Оптимистичное обновление обязательно,
   отклик < 50 мс. Бриф, запрет №1
2. **Чанки консоли обязаны быть в Workbox precache.** Ленивый чанк без
   предзагрузки в офлайне недоступен: судья откроет консоль в зале без сети и
   получит пустой экран. Сейчас это обеспечено тем, что precache берёт весь
   собранный набор целиком; автотеста на это ещё нет — см. технический долг
   в `docs/05-state.md`
3. **Бюджет < 400 КБ gzip на набор чанков консоли.** Тяжёлое из публичной части
   (графики, карты) сюда попадать не должно. Импорты из публичных фич в
   `features/console` запрещены

Из этого же следует, почему компоненты маршрутов не экспортируются: экспорт
отключает вынос компонента в отдельный чанк, и ленивая загрузка перестаёт
работать. Правило `react-refresh/only-export-components` для `src/routes`
поэтому выключено.

Требования к консоли целиком — `docs/02-requirements.md`, раздел 6.

## Сессия

Вход по одноразовому коду — ТЗ 2.1, контракт ТС 7.1. Пароля нет.

Refresh-токен живёт в `localStorage`, access-токен только в памяти. Истёкший
access-токен обновляется прозрачно, один повтор запроса, одна попытка
обновления на все параллельные запросы. Маршруты аутентификации помечены
`anonymous` — иначе отказ на `/auth/refresh` запускает обновление, которое
дожидается само себя. Обоснование целиком — ADR-017.

**Кода в пилоте пока взять неоткуда:** провайдера СМС нет (ОВ-9), код уходит
в лог бэкенда, а логовый адаптер намеренно не собирается при
`NODE_ENV=production`.

## Обновление приложения

Service worker не обновляется сам: перезагрузка вкладки может застать судью
посреди турнира. Пользователь видит предложение и решает сам.

## Иконки

`public/icons/*` — временные заглушки, рисуются `pnpm make:icons` без
зависимостей. Заменяются, когда появится дизайн.
